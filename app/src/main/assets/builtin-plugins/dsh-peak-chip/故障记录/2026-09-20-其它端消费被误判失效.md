# 故障：同一账号上别的客户端消费，被判成"指示灯失效"

> ⚠️ **本记录已脱敏**：账户余额、金额、时分秒一律替换为占位符（`A1`…`An` 按原值升序编号，故大小关系仍可读），非真实账户数值。


**日期**：2026-09-20
**版本**：4.0.6 → 4.0.7
**现象**：用户重启 dsh web 后指示灯显示**失效**；用户自己怀疑"是不是我在电脑端用 dsh 导致的"。

## 一、现象与数据

settings 里 `dsh-peak-chip.dbgLog` 的 48 个真实窗口（hh:mm → hh:mm）：

| 时间 | 本地估算 L | 账号口径 S | 旧口径 E=\|S−L\| | 该窗余额变化 | 本窗本地消费 |
|---|---|---|---|---|---|
| hh:mm | ⟨金额⟩ | A8 | ⟨金额⟩ | −A2 | ⟨金额⟩ |
| **hh:mm** | ⟨金额⟩ | A9 | **⟨金额⟩** | **−A5** | ⟨金额⟩ |
| **hh:mm** | ⟨金额⟩ | A11 | **⟨金额⟩** | **−A3** | **0** |
| **hh:mm** | ⟨金额⟩ | A13 | **⟨金额⟩** | **−A4** | ⟨金额⟩ |
| hh:mm | ⟨金额⟩ | A14 | ⟨金额⟩ | −A1 | 0 |

关键行是 hh:mm 和 hh:mm：**本机一窗没花（0 / ⟨金额⟩），余额却掉了 A3 / A4** —— 同一个 DeepSeek 账号上还有别的消费者（电脑端 DSH）。E 从 ~1.8 跳到 A6，连续 3 窗越线 → 锁存，之后再没恢复（`errorStreak` 一路涨到 18）。

## 二、根因

旧口径 `E = |S − L|` 里：
- `S = max(0, V + T)` 是**账号口径**的今日消耗（余额变化 + 充值）；
- `L` 只是**本机**的估算。

余额是**账号级**的，所以任何别的客户端花的钱都会进入 S 而不进入 L，差额直接算成"误差"。**这不是记账 bug，是口径把两件事混成了一件。**

## 三、修法

利用一条恒等式：**账号总共花的钱 ≥ 本机花的钱**（本机也是账号的一部分）。于是把差额切成两半：

```
O 其它端消费 = max(0, S − L)    账号 > 本机 → 别的客户端花的（正常）
E 误差       = max(0, L − S)    本机 > 账号 → 不可能，除非本机多算（异常）
```

- 阈值与连续窗容错不变（E ≥ 2 连续 3 窗才锁存），但判据换成新的 E。
- 详单加一行「其它端消费」，把"为什么对不上"先解释掉，误差那行才不会被误读成故障。
- **不再拿误差方向教用户去加减手动充值**：旧版在"别的客户端也在花"时会给出完全错误的建议（把电脑端消费说成"本地偏低、充值偏大"）。

## 四、附带修的：锁存是粘的，口径变了必须主动作废

锁存当天不恢复（跨日才复位）。口径一换，旧口径判出的"失效"就是错的，不处理用户要等到第二天。所以引入 `RULE_VERSION`：状态里的版本号与代码里的不一致时，**一次性**清掉 `errorLatched` / `errorStreak` / `otherSpent` 并按新口径重算。

## 五、验证

`tests/v4-other-client.mjs`（**拿上面那 48 个真实窗口回放**）：

| 断言 | 结果 |
|---|---|
| 新口径整段回放**从未锁存** | ✅ 0 窗 |
| 最后 O = ⟨金额⟩（正好是那段差额） | ✅ |
| 最后 E = 0 | ✅ |
| **反向验证**：旧口径在同一份数据上确实锁存 | ✅（否则这测试抓不到回归） |
| 切分函数单测（两个方向、相等、脏数据） | ✅ 4 条 |
| 口径迁移清掉旧锁存、且只做一次 | ✅ 4 条 |

另外三套（记账 / 客户端假 DOM / 漂移）改完断言后仍全绿。

## 六、教训

1. **"本地估算"和"账号余额"是两个口径，任何直接相减都在假设"只有本机在花"。** 一旦有第二台设备，这个假设就破了 —— 而它破得很安静：数字看起来还挺合理（3.5 元）。
2. **粘性状态要跟口径绑定版本号。** 判定规则改了，旧规则留下的状态就是脏数据；靠"明天自然会好"不是设计，是拖延。
3. **回放实时账本的断言不能写死终值** —— 这轮又踩了一次：账本在测试期间继续增长，`L=A10` 变成 `A12`，写死的断言就红了。改成拿"日志最后一窗"当期望（自洽检查），并断言回放能重现真实轨迹。
4. **纯函数要能单测到边界**：把切分抽成 `splitResidual()` 之后，"本机多算"这一类在端到端场景里会被充值台阶检测吸收（模型固有盲区），只有单测能把它钉住。这条盲区已经写进代码注释。
