
# 依赖

| 类别 | 内容 | 缺了会怎样 |
|---|---|---|
| 运行时 | dsh 自带 Node（宿主）+ 浏览器（客户端） | 装不上 |
| 包（peer） | 见 `package.json` 的 `peerDependencies`（`dsh-home-paths`、`dsh-settings`、`dsh-credentials`、客户端 UI 相关） | 加载失败 |
| 服务 | `api.deepseek.com`（余额接口，缺 key 时返回 401 也算通） | 拿不到余额，指示灯失效（会显式标"失效"） |
| 服务 | `127.0.0.1:3090` DSHA 桥 | **降级**：充值按钮**点了没反应**（详见下面「缺桥时的真实行为」），其余功能正常 |
| 能力 | `network-out`（必需）、`gui-web`（面板必需）、`dsha-bridge`（非必需） | 见上 |
| 凭据 | DeepSeek API key（在 dsh 设置里配，不在本插件里） | 拿不到余额与用量 |

## 缺桥时的真实行为（v4.1.7 修正一处**写错的**说法）

旧版这里写"缺桥会退回 `window.open`"—— **不成立**。客户端只在 **settings 通道不可用**时才 `window.open`；
而"通道可用但 3090 桥不存在"（电脑端就是这样）时，客户端照常把请求写进 settings，宿主读不到桥 token →
**充值按钮点了毫无反应**，只在宿主日志里留一条 `读不到桥 token`。

- 电脑端变体（`pc/dsh-peak-chip`）的修法：宿主在拿不到桥时用 `node:child_process` **开系统默认浏览器**
  （记在 PC 侧 `声明.md` 里）。手机侧有桥，不涉及；将来若搬到没有桥的平台，照这个思路补。
- **正确做法**（本轮决定只改文档不动代码）：这条差异以文档形式随变体走，避免两个变体各写一套没验证过的逻辑。

## 已知环境差异（PC 侧实测，本机未复现）

- **`corner-shape`（Chromium 139+）**：产品样式表把全局角形设成 squircle，于是 `border-radius:50%`
  会被画成**圆角方**。本机 WebView 不认这个属性、所以怎么测都是圆的；PC 侧 Edge 认，**必须显式补
  `corner-shape:round!important`**（产品自己也给 spinner/dot/tag/switch 逐个 opt-out）。
  本变体**未加**这行（手机侧无影响）；若哪天手机 WebView 升到 139+ 且圆点变圆角方，就是它。
- **排错纪律**（PC 侧踩出来的）：别拿截图像素反推角形（抗锯齿会被宽松阈值算成实体，把圆读成圆角方），
  先用 `getComputedStyle`（含 `cornerShape`/`clipPath`/`mask`）与 `elementsFromPoint` 让运行期回答。

**平台**：手机（mobile）已验。v4.1.7 起**代码里没有写死的 DSH_HOME**（`resolveDshHome()` + `import.meta.url` 自定位，测试也改成相对自身定位），所以搬到别的 DSH_HOME 下能直接跑；电脑端仍未适配的原因只剩 3090 桥（Windows 侧没有）。
