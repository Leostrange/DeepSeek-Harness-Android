
# dsh-peak-chip（峰谷指示灯）

**会话头部一个圆点 + 面板显示本日消耗与余额。** DeepSeek 定价分峰谷，这个插件把"今天花了多少、余额还剩多少"摆在眼前。

| 项 | 值 |
|---|---|
| 作者 | 本机 DSH 自己写（手机 DSHA 的 `plugin-src/dsh-peak-chip`；不写死绝对路径，见 `环境.md`） |
| 版本 | 4.1.8 |
| 最后更新 | 2026-09-24 |

## 入口

- 宿主半边：`lib/index.js`（轮询余额、记账口径 `accountDay()`）
- 客户端半边：`lib/client.js`（面板与详单，零构建单文件）
- 自带 skill：无；故障与口径记录在 `故障记录/`

## 怎么装

```
dsha-plugin import dsh-peak-chip-4.1.8.tgz
```
装完**重启 dsh web**，并在浏览器里刷新页面。

## 接触面

- 读 `$DSH_HOME/.bridge_token`（用于充值按钮走 DSHA 桥）
- 连 `api.deepseek.com`（余额查询）、`127.0.0.1:3090`（桥）
- 写 settings 命名空间 `dsh-peak-chip`（余额、今日消耗、充值识别结果、调试窗口、自身路径 `selfDir`/`manualPath`）

## 边界（明确不做）

- 不代替官方计费：所有数字是**本地审计 + 余额变化推算**，误差会显示出来
- 不改模型路由、不改定价参数、不自动充值
- 缺桥时只降级"充值按钮"，面板与记账不受影响

## 记账口径（一句话）

`本地审计 L`（按本机 token 折的价）与 `本日消耗 S = max(0, V + T)`（`V = 当日首次余额 − 当前余额`）各算一遍；差额按方向拆成 `O = max(0, S − L)`（面板上的「无法审计」：同账号别的客户端花的，正常）与 `E = max(0, L − S)`（误差：本机多算才可疑）。充值靠余额台阶检测（中位数滤波 + 连续窗确认），判定权只有宿主一处。
