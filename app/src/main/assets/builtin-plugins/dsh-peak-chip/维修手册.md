# dsh-peak-chip 维修手册

> **给接手维修的 agent 看的**（不是给用户看的）。用户说"指示灯坏了""修一下这个插件"就从这里开始。
>
> **两个入口**：① 面板详单**最底下**的「一键维修」大红按钮 —— 它把一段指路消息**填进输入框**（不自动发送），
> 发送是用户按的；如果这段消息就是你的开场白，那你是被那个按钮请来的。② 用户直接把本文件路径发给你。
>
> **本文件在哪**：绝对路径由宿主算出来写在 settings 命名空间 `dsh-peak-chip` 的 `manualPath`（及 `selfDir`）里，
> 各实例不同（Windows 那边没有 `$DSH_HOME`）。提示词里的路径若在本机不存在，先查这两个字段，
> 或 `dsha-plugin list | grep peak-chip` 确认它装在哪 —— **不要假设 $DSH_HOME 一定对**。
> ⚠️ 客户端半边整体挂掉时按钮也不在了（同一批客户端插件一起挂）—— 那就只能走 ②。
> 本手册和源码一起进油纸包（`$DSH_HOME/plugin-kits/dsh-peak-chip/*.tgz`），不需要注册成 skill。

## 〇 维修契约（先读这一节；修完必须兑现）

**修好不算完。** 你多半是被面板底部的「一键维修」按钮请来的（它只负责把话填进输入框）。
按本手册修完的 agent，有义务把这一轮学到的东西**回灌进文件与测试** ——
这是这个插件"理论上不会彻底失效"的唯一原因：每一轮维修都让手册更完整，下一轮更省事。

| 你修的是什么 | 必须同时更新 |
|---|---|
| 官方价目表 / 峰谷时段 / 法定节假日 | 两半边的表（宿主 `lib/index.js` 的 `PRICES`、`PEAK_WINDOWS`、`HOLIDAY_RANGES`；客户端 `lib/client.js` 的 `PRICES`、`PEAKS`、`HOLIDAY_RANGES`）+ 跑 `node tests/sync.mjs` 证明两份一致 + `计费算法说明.md`「参数及来由」写上新数字与日期 |
| 口径 / 阈值 / 公式 / 判定规则 | `RULE_VERSION` **加一**（不升 → 旧锁存变成假红灯，有事故记录）+ `计费算法说明.md` 变更记录一行 + 对应测试断言 |
| 面板 / 交互 / 提示文案 | `开发日志.md` 一条 + `tests/v4-client.test.mjs` 断言（写完要**反向验证**：旧代码代进去必须失败） |
| 任何一次维修 | `开发日志.md` 追加一条：日期 · 用户原话 · 根因 · 改了什么 |
| 排查出的**故障** | `故障记录/YYYY-MM-DD-<现象>.md` 写一篇（症状 → 证据 → 根因 → 处置） |
| 发现本手册缺步骤 / 写错了 | **当场补进本手册**，别只在回复里说 |
| 全部改完 | `node $DSH_HOME/tools/kit.mjs pack dsh-peak-chip --with-tests` 重新封包（测试不过不许封）。**本机没有 `kit.mjs` 的实例见 §二末的等价做法** |

五条硬要求（本机纪律，别绕）：

1. **先问用户"发生了什么"—— 别一上来就跑测试、翻代码、下结论。** 症状是用户给的，不是日志给的。
   至少问清四件事：**① 什么时候开始的**（今天？刚才？哪一次操作之后？）；**② 你在面板上看到什么**
   （哪个数字不对、圆点什么颜色、详单里哪一行可疑）；**③ 之前动过什么**（充值过？换过模型 / 账号 /
   密钥？改过设置？重启过？装过别的插件？）；**④ 你期望它是什么样**。
   用户说不清就继续问 —— **症状不清时不进入 §一 的分类，更不许动代码**。
   （用户原话：「先谈清楚再开工」；症状 ≠ 需求。）
2. **先诊断、摆证据、等人点头再改。** 拿到症状再去查，把证据、根因、拟改动摆给用户，点头才动手。
3. **测试不过不算修好。** 六套测试 + `sync.mjs` 全绿才算（§七）。
4. **重启 Web 是用户的动作。** agent 不许重启自己所在的进程。
5. **修不动就诚实收口。** 例如官方下线该接口、或计费体系整体换掉 —— 这种情况**不算失职**，
   但必须做三件事：把结论与证据写进本手册（新增一节"已知不可修"）、把 `RULE_VERSION` 那条路
   留给下一个能修的人、明确告诉用户"这个插件在当前体系下修不了"。**假装修好才是失职。**

## 一 先分清是哪一类故障

> **前提：症状来自用户，不是来自日志。** 先按 §〇 第 1 条问清"发生了什么"，
> 拿到用户原话与"面板上看到什么"，再对着下表定位。**跳过问、直接跑测试或翻代码 = 违规。**
> 表里对不上、或用户描述含糊时，回到提问，别硬猜一节来修。

| 症状 | 大概率是 | 去哪节 |
|---|---|---|
| 指示灯红/灰、本日消耗离谱、误差行一直不绿 | 世界变了（官方改价 / 改峰谷 / 改口径） | §三 |
| 面板空白、数字不动、页面里根本没有指示灯 | 客户端半边挂了（**同一批客户端插件会一起挂**） | §四 |
| 日志里没有 `[dsh-peak-chip]`、插件像不存在 | 安装 / 接线 | §五 |
| 手动改充值不生效、数字来回跳 | 请求通道或显示层 | §六 |

数据流速查：宿主每 `refreshMinutes`（默认 5）查一次官方余额 → `accountDay()` 算出当日账 → 写 settings 命名空间 `dsh-peak-chip` → 浏览器半边读快照渲染面板。**判定权只有一处**（宿主），客户端只负责显示。

## 二 动手前：先确保能回退

```bash
node $DSH_HOME/tools/kit.mjs verify dsh-peak-chip --against=$DSH_HOME/plugin-src/dsh-peak-chip  # 现在的源码 vs 最近一次快照
node $DSH_HOME/tools/kit.mjs list                                                              # 有哪些快照、还完好吗
dsha-plugin rollback dsh-peak-chip                                                             # 回退上一版
node $DSH_HOME/tools/kit.mjs restore dsh-peak-chip --apply                                     # 从油纸包还原（先自动备份当前目录）
```

- 源码目录：`$DSH_HOME/plugin-src/dsh-peak-chip/`。
- `$DSH_HOME/profiles/web/node_modules/dsh-peak-chip` 是它的**软链** —— 改源码就等于改了已装插件，不需要 `import`；改完**等用户重启 Web** 生效。

### 二末：本机没有 `kit.mjs`（或源码不在 `plugin-src/`）时的等价做法

上面的命令按**作者那台机器的布局**写：源码在 `$DSH_HOME/plugin-src/<插件名>/`，
快照工具是 `$DSH_HOME/tools/kit.mjs`。**`kit.mjs` 不随插件发布**，别的实例不一定有；
从 Release 包安装的实例，源码也可能只在 `profiles/*/node_modules/<插件名>/` 下。

先定位真实位置（别假设）：读 settings 命名空间 `dsh-peak-chip` 的 **`selfDir` / `manualPath`**
（宿主用 `import.meta.url` 算好的绝对路径），或 `dsha-plugin list`。

然后按下表降级 —— **维修契约本身不变**（照样先诊断、测试不过不算修好）：

| 手册里的命令 | 没有 `kit.mjs` 时 |
|---|---|
| `kit.mjs pack <名> --with-tests` 重新封包 | 在插件目录里跑 **`npm pack`**（包内自带 `package.json`，产出结构相同的 `.tgz`）。**测试全绿再打** |
| `kit.mjs verify --against=…` 源码 vs 快照 | 该目录是 git 仓库就用 `git diff`；否则与上一版 `.tgz` 解包后对比 |
| `kit.mjs list` 看有哪些快照 | 看 Release 里有哪些版本；或自己留一份"当时能跑的 tgz" |
| `kit.mjs restore --apply` 从油纸包还原 | 用上一版 `.tgz` 重新 `dsha-plugin import`；**动手前先 `cp -a` 备份整个插件目录** |
| `dsha-plugin rollback <名>` | 这条是 DSHA 自带，任何实例都能用 —— **优先用它** |

> **一句话**：`kit.mjs` 只是"油纸包"的便利工具，不是维修的前提。
> 维修真正的前提是**源码、本手册、测试都在本地**（它们都随包发布）—— 这一点在任何实例上都成立。

## 三 世界变了：官方改价 / 改峰谷 / 改节假日

**去哪查（唯一权威来源）**：<https://api-docs.deepseek.com/zh-cn/quick_start/pricing>
（2026-09-21 实测可访问，当时页面数字与本插件一致）

怎么读：三行 × 两列 —— 行是 `百万tokens输入（缓存命中）`／`（缓存未命中）`／`百万tokens输出`，列是 `空闲时段`／`高峰时段`。

**填到哪**（数组顺序固定是 `[空闲, 高峰]`，三个键含义：`hit` 命中 / `miss` 未命中 / `out` 输出）：

| 官网格子 | flash 行 | pro 行（`deepseek-v4-pro`） |
|---|---|---|
| 命中 空闲/高峰 | `hit: [0.02, 0.04]` | `hit: [0.15, 0.30]` |
| 未命中 空闲/高峰 | `miss: [1, 2]` | `miss: [4.5, 9.0]` |
| 输出 空闲/高峰 | `out: [4, 8]` | `out: [13.5, 27.0]` |

（表里是 2026-09-21 的值，只作"填哪个位置"的对照；真值以官网为准。）
**宿主与客户端两份都要改**，客户端那份只是多了 `name` 字段。

**峰谷时段**：官网口径 = 北京时间周一至周五（**不含法定节假日**）9:00–12:00、14:00–18:00 为高峰，其余为空闲。
→ 宿主 `PEAK_WINDOWS = [[9 * 60, 12 * 60], [14 * 60, 18 * 60]]`（分钟数）；客户端 `PEAKS` 同形状。两份必须一致。

**法定节假日**：查「国务院办公厅关于 <年份> 部分节假日安排的通知」（gov.cn）。
⚠️ 本手册写这一版时**没记当时用的链接** —— 谁第一次用它修，就把当时用的链接补进这一行。
→ 宿主/客户端 `HOLIDAY_RANGES = [['起','止','名称'], …]`（日期用 `YYYY-MM-DD`）。

**验收**：
```bash
cd $DSH_HOME/plugin-src/dsh-peak-chip
node tests/sync.mjs && node tests/v4-scenarios.test.mjs && node tests/v4-alert.test.mjs
```

**灰灯（永久故障）不是"没法修"**：它表示"口径已经不成立，等人来改"。改完价目表/口径后 `RULE_VERSION` 加一，`lib/index.js` 里那条迁移会把灰清掉。

## 四 客户端半边挂了

症状：页面里没有指示灯、面板空白、数字长时间不动。**同一批客户端插件会一起挂**，别只盯这一个。

1. 开浏览器 console 看报错（**客户端异常不写宿主日志**）。
2. `node --check lib/client.js` —— 语法错是整批挂掉最常见的原因。
3. 零构建契约：客户端半边**不能**用 `import` / TS / JSX；只能 `window.__ModuleLoader__.load({ id, factory })`。
4. `exports.name` / `exports.inject` / `exports.apply` 三个都要在；`inject` 写了**没人提供**的服务名 → 永远等待、静默不生效（最难查的一类）。
5. 重复挂载会出现两个指示灯：用 `window.__xxxOwner` 认领所有权，清理时只在自己仍持有所有权时删 DOM。
6. 定位锚点用稳定属性（本插件用 `data-conversation-header-corner`）；不要搬 React 拥有的节点。

## 五 插件没加载 / 像不存在

```bash
dsha-plugin list | grep peak-chip                            # enabled: true 不代表加载成功
grep -n peak-chip $DSH_HOME/profiles/web/package.json
ls -l $DSH_HOME/profiles/web/node_modules/dsh-peak-chip      # 应指向 plugin-src
```

- 启动日志里没有 `[dsh-peak-chip]` ＝ 没进去，或启动期抛错。
- **空的 `catch {}` 会吞掉 `ReferenceError`**（本机真事故：`join is not defined` 表现成"指示灯莫名其妙黑了"）。
- 一切副作用必须包 `ctx.effect`，否则热更后残留双定时器。

## 六 手动充值不生效 / 数字来回跳

数据流：客户端 `commitTopUp` 用**一次** `mutate` 写 `manualTopUp` + `previewNow` → 宿主 `scope.watch` 看到 `previewNow` 变大 → `runPreview()` **单独取一次余额** → 写 `preview*` 字段 → 面板顶替显示 → 下一窗 `accountDay` 正式认领（`appliedManual`）。

| 症状 | 查这里 |
|---|---|
| 确认后先跳回旧值、约 1 秒后才变 | 客户端本地回声 `topUpEcho` 没生效（显示优先级：**本地回声 > 宿主预览 > 正式值**） |
| 一直不更新（连旧的都不动） | `previewNow` 没写进去，或宿主 `watch` 没触发 |
| 星号一直不消失 | 正常窗没跑成功（看 `error` 字段；网络失败按原节奏等下一轮） |
| 只想确认数据 | settings 命名空间 `dsh-peak-chip` 的 `preview*`、`manualTopUp`、`appliedManual` |

红线：**客户端不许自己算 `S`/`E`、不许自己判告警**；预览与正常窗必须共用 `accountTotals()` / `splitResidual()`，不允许出现第二份口径（v4.0.6 的故障就是这么来的）。

## 七 改完的验收与生效

```bash
cd "${SELF_DIR:-$DSH_HOME/plugin-src/dsh-peak-chip}"   # 位置以 settings 的 selfDir 为准（§二末）；作者本机是这个路径
for t in tests/v4-*.test.mjs tests/v4-other-client.mjs tests/sync.mjs; do printf '%-32s' "$t"; node "$t" >/dev/null 2>&1 && echo ✓ || echo ✗; done
node $DSH_HOME/tools/kit.mjs pack dsh-peak-chip --with-tests   # 有红就不封包；没有 kit.mjs 就用 npm pack（§二末）
```

- 归档的废弃套件（`tests/_*.mjs`）**不随包发布** —— 它们写死了作者本机的路径、且引用的账本文件已删，跑必然红。要查"为什么被推翻"看 `开发日志.md` 的版本史与 git 历史。
- 生效：客户端改动**刷新页面**通常就够；宿主半边改动要**用户重启 Web**。
- 回复用户必须说清三件事：**改了什么 · 怎么验证 · 要不要重启**。

## 八 本手册自己的维护

- 每次维修发现手册没写的坑 → **当场加一节**；写错了就改，不留"已废弃"段落。
- 契约（§〇）那张表是手册的"活页"：出现新的维修类型，就在表里加一行 —— 加行本身就是履行契约。
- 手册与源码一起进油纸包（`pack` 收所有 `*.md`）。
