# Исследование прозрачности DSHA — 2026-10-05

## Вывод

Для базы DSH 0.1.7-rc.2 следует сохранять нейтральное оформление и переносить отдельные исправления dsh-any-background. Полное обновление плагина до 0.3.5 нарушит требование пользователя: его клиентские и серверные значения по умолчанию задают прозрачность большинства областей 50% и размытие 30 px. Открытие настроек не должно применять или сохранять такие значения.

Исследованы публичные заголовки и тела issues/PR DSHA, выбранные обсуждения, исходники текущего main DSHA и плагина. Это не проверка всех комментариев всех обращений и не испытание новой версии на устройстве.

## DSHA: issues и PR

- [Issue 60](https://github.com/DSH-APP/DSHA/issues/60): скрытые при отсутствии hover кнопки строки сессии. Закрыто; касается прозрачности элементов управления, а не всех поверхностей приложения.
- [Issue 72](https://github.com/DSH-APP/DSHA/issues/72): предложение добавить dsh-any-background в каталог. Открыто; не исправление прозрачности.
- [PR 44](https://github.com/DSH-APP/DSHA/pull/44): намеренно прозрачное плавающее окно QuickChat. Закрыт без слияния. Принудительную прозрачность WebUI из него нельзя переносить в обычное окно приложения.
- [Issue 84](https://github.com/DSH-APP/DSHA/issues/84): нативное переключение светлой/тёмной темы мешает WebView следовать настоящей системной теме. В текущем main появился выбор system/light/dark. Это отдельная проблема согласования темы; она не объясняет самопроизвольную прозрачность плагина. Нельзя при таком переносе принудительно переписывать сохранённые настройки веб-темы.

Готового issue/PR DSHA, точно описывающего превращение всех поверхностей в прозрачные при открытии вкладки «Темы», в исследованных материалах не найдено.

## Более точные обращения в репозитории плагина

- [Issue 15](https://github.com/Tkingxiao/dsh-any-background/issues/15): версия 0.2.8 безусловно добавляла position:fixed и z-index:26 панели; на мобильном экране это приводило к перекрытию полупрозрачным слоем. Убирать навязанные геометрию и stacking, а не повышать z-index всех окон.
- [Issue 13](https://github.com/Tkingxiao/dsh-any-background/issues/13): карточка чата width:100% с padding и border в content-box выходит за экран. Для явно включённого карточного оформления использовать border-box и восстанавливать стили при отключении.
- [Issue 11](https://github.com/Tkingxiao/dsh-any-background/issues/11): мобильная шапка находится вне центральной области; очистка фона общей рамки делает шапку прозрачной. Нужна обработка реального слоя шапки, а не общая прозрачность контейнеров.
- [Issue 20](https://github.com/Tkingxiao/dsh-any-background/issues/20): список совместимости пропускал 0.1.7-rc.2; поддержка расширена в 0.3.2.
- [Issue 24](https://github.com/Tkingxiao/dsh-any-background/issues/24): обрезание карточки разрешений с плагином 0.3.4 на DSH 0.1.7-rc.2. Нужно отдельно проверять доступность кнопок подтверждения при включённом blur; закрытие issue само по себе не доказывает исправление нашей сборки.

## Полезные исходники и изменения

Изучена версия 0.3.5, commit [f6093fa](https://github.com/Tkingxiao/dsh-any-background/commit/f6093fa270c10977941bb0c49ea5d513d8e12a6e).

- [Ненейтральные значения по умолчанию](https://github.com/Tkingxiao/dsh-any-background/blob/f6093fa270c10977941bb0c49ea5d513d8e12a6e/src/client/state.ts): sidebar/card/input/settings/chatText/trajectory/panel/produced opacity 0.5; большинство blur 30. Брать целиком нельзя.
- [Адаптер именно 0.1.7-rc.2](https://github.com/Tkingxiao/dsh-any-background/blob/f6093fa270c10977941bb0c49ea5d513d8e12a6e/src/client/host-compat/versions/v0-1-7-rc-2/adapter.ts): меню рисует дочерний MenuSurface, которому нужны --dsw-menu-surface-fill и --dsw-menu-backdrop-filter; изменение только внешнего role=menu недостаточно. Настройки используют portal в body. Внешняя рамка панели остаётся неподвижной, blur должен принадлежать внутреннему содержимому.
- [0.3.0](https://github.com/Tkingxiao/dsh-any-background/commit/61ae33ca0342e84a224836a74d8369539fde20f2): исправления рамки/позиционирования панелей 0.1.7 и циклических fallback CSS-переменных.
- [0.3.2](https://github.com/Tkingxiao/dsh-any-background/commit/630e6b606248f6794e8eae2abad16b28793dfa1c): явная поддержка rc2 и более узкий селектор окна настроек, исключающий посторонние confirmation dialogs.

## Состояние DSHA upstream

Последний опубликованный релиз — [v0.1.7-rc2](https://github.com/DSH-APP/DSHA/releases/tag/v0.1.7-rc2), build147. Однако main уже содержит build157 с DSH 0.2.0-rc.2: [исходники build157](https://github.com/DSH-APP/DSHA/commit/9120b874fa0d2148c30ea0be36fa1c6e4e984952). Это не новый опубликованный APK.

Полезные отдельные изменения: трёхрежимная нативная тема и [устранение дублирования архива runtime/recovery](https://github.com/DSH-APP/DSHA/blob/main/docs/releases/build157-changes.en.md), уменьшающее упаковку примерно на 122.7 MB при сохранении независимой рабочей директории восстановления. Обновление всего runtime до 0.2.0 требует отдельной проверки совместимости и не нужно для ремонта opacity.

## План для нашей сборки

1. Сохранить исправления Test17: opacity 100%, blur 0 по умолчанию; только явно заданные параметры активируют overrides; чтение настроек не пишет конфигурацию; запуск и открытие вкладки не извлекают цвет автоматически; reset/dispose возвращают принадлежащие плагину исходные стили.
2. Выборочно перенести rc2-обработку MenuSurface, portal настроек и узкий селектор settings dialog. Не переносить новые полупрозрачные defaults или глобальные прозрачные фоны.
3. Любые дополнительные host-стили применять только при явном включении соответствующего эффекта, запоминать прежнее значение и снимать при отключении. Существующие пользовательские настройки не стирать и не заменять.
4. Проверить первый запуск, открытие всех вкладок темы, перезапуск без изменений, явное сохранение/сброс, светлую/тёмную тему, телефон/планшет, меню и окна разрешений. Сравнивать computed backgrounds/opacity и записи конфигурации до/после.

В Test17 уже устранены безусловная геометрия панелей и прозрачные fallback при незаданных CSS-переменных. Регрессия на извлечённом клиенте Test16 воспроизводила прозрачность восьми поверхностей; исправленный клиент проходил проверку. Это доказательство локального исправления, а не испытание upstream 0.3.5. В этом исследовании исходники приложения и APK не менялись; сохранён только данный отчёт.
